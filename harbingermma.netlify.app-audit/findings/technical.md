# Technical SEO findings: harbingermma.netlify.app (pre-launch staging)

Audit date 2026-10-12. Score: **58/100**.

| Category | Status |
|---|---|
| Crawlability | Fail (staging robots open; broken internal link) |
| Indexability | Fail (staging duplicate risk, no redirects) |
| Security headers | Weak (HSTS only) |
| URL structure / redirects | Pass on slashes, Fail on migration |
| Mobile | Pass |
| JS rendering | Pass (static HTML, no CSR dependency) |

## What works
- All pages are static HTML (Astro static output), `is_spa=false`. Content, canonical and JSON-LD are in the raw HTML, so no rendering risk.
- Viewport meta present, `lang="en"`, hero image `fetchpriority="high"`, explicit width/height on logos, only three scripts, Google font preconnect.
- HSTS served (`max-age=31536000; includeSubDomains; preload`). HTTPS only.
- Sitemap index at `/sitemap-index.xml` and `/sitemap-0.xml` are valid, 18 URLs, matching the inventory.
- Trailing-slash handling is consistent: `/classes` 301s to `/classes/` in one hop, matching `trailingSlash: "always"`. `/index.html` returns 200 but is not linked (Info).
- Custom 404 page returns a true 404 status (4.8 KB).

## Findings

### 1. [Critical] Staging robots.txt is open, and the staging guard in the code does not work
- Evidence: `https://harbingermma.netlify.app/robots.txt` returns `User-agent: * / Allow: /` with `Sitemap: https://harbingermma.com/sitemap-index.xml`. `robots.txt.ts` is meant to return `Disallow: /` on non-production hosts, but it tests `site.hostname`, and `site` is the build-time `astro.config.mjs` value. The deploy was built with the production `site` (apex), so the check is always true. The staging sitemap is also reachable at `/sitemap-index.xml`, and the `Sitemap:` line points at the production host (404 today, stale for the sitemap_discovery helper, which only found the sitemap via fallback). No `X-Robots-Tag` or meta noindex exists.
- Risk: the staging copy is an indexable full duplicate of the new site. Its canonicals point at harbingermma.com, which Google may treat as a hint only, and the production host currently serves different (Webflow) content.
- Recommendation: add a Netlify header `X-Robots-Tag: noindex, nofollow` for the staging context only, and put Disallow in robots for staging by deciding on a build-time env var rather than `site.hostname`. Do not ship the staging-only header to production.
  - `netlify.toml`:
    ```
    [context.branch-deploy.environment]
      SITE_ENV = "staging"
    [context.deploy-preview.environment]
      SITE_ENV = "staging"
    [[headers]]
      for = "/*"
      [headers.values]
        X-Robots-Tag = "noindex, nofollow"
    ```
    (Scope the noindex header to the staging/netlify.app context only. If the production site is a separate Netlify site, set it in that staging site only. Otherwise put it in a staging-only `_headers` file generated by the build.)
  - `src/pages/robots.txt.ts`: switch to `import.meta.env.SITE_ENV !== "staging"` (or `process.env`), not `site?.hostname`.
  - Also add `<meta name="robots" content="noindex">` in the layout when `SITE_ENV=staging`.
- Source files: `src/pages/robots.txt.ts`, `astro.config.mjs`, new `netlify.toml`, layout head.
- How we'd know it failed: `curl -sI https://harbingermma.netlify.app/ | grep -i x-robots` is empty, or `site:harbingermma.netlify.app` returns results in Google.
- Launch caution: before cutover verify production robots.txt shows `Allow: /` and no `X-Robots-Tag: noindex` (the classic launch-day blocker).

### 2. [Critical] No redirects for old Webflow URLs (migration)
- Evidence: the old site (www.harbingermma.com) serves /about, /apply, /contact, /class-types/bjj, /collections/apparel and /announcements/schedule-changes (all 200 now). The new site has no `_redirects` or `netlify.toml`, and unknown paths 301 to the slash version and then 404 (two hops to a dead end).
- Impact: loss of inbound links and ranking equity, 404s for bookmarks, Google Business Profile and social links.
- Recommendation: add `public/_redirects` (copied to the output root by Astro). Proposed map below. Netlify matches `/x` and `/x/` equally, so one rule covers both, and `301!` is not needed. Put specific rules above wildcards.

```
# Old Webflow -> new Astro (harbingermma.com). Place in public/_redirects
/home                              /                      301
/announcements/schedule-changes    /schedule/             301
/class-types/all                   /classes/              301
/class-types/bjj                   /classes/bjj/          301
/class-types/conditioning          /classes/conditioning/ 301
/class-types/striking              /classes/muay-thai/    301
/class-types/mma                   /classes/              301
/class-types/yoga                  /classes/              301
/about                             /coaches/              301
/apply                             /#claim-trial          301
/contact                           /#claim-trial          301
# Shop collections: verify exact destinations on shop.harbingermma.com first
/collections/apparel               https://shop.harbingermma.com/collections/apparel    301
/collections/accessories           https://shop.harbingermma.com/collections/accessories 301
/collections/equipment             https://shop.harbingermma.com/collections/equipment   301
# Legal: build pages first, then enable these (do NOT redirect to home; that is a soft 404)
# /privacy-policy                  /privacy-policy/       (page must exist at the same slug)
# /liability-waiver                /liability-waiver/
# /minor-liability-waiver          /minor-liability-waiver/
# /minor-competition-release-waiver /minor-competition-release-waiver/
```
Mapping rationale and open decisions:
  - Cleanest option for legal pages: create `src/pages/privacy-policy.astro`, `liability-waiver.astro`, `minor-liability-waiver.astro`, `minor-competition-release-waiver.astro` at the same slugs, so no redirect is needed (Astro's slash redirect handles the rest). Waivers likely are linked from signup flows and emails.
  - `/about` has no equivalent. `/coaches/` is the nearest content, but a real About page (or the homepage) is a product decision. Do not point it to a 404.
  - `/class-types/striking` is split: Muay Thai is the best match, boxing is the alternative. `/class-types/mma` and `/yoga` have no page (yoga is not offered on the new site). They go to `/classes/` until pages exist.
  - Fragment targets (`/#claim-trial`) work in Netlify but analytics may drop the fragment. Consider a dedicated `/contact/` page instead, which is also better for local SEO (NAP, map, hours). If built, use `/contact /contact/` and `/apply /contact/`.
  - Old coach, blog or CMS item URLs were not discoverable: the old site returned no usable sitemap (`/sitemap.xml` 404 on www). Before launch, export Webflow's page list and Search Console "Pages" and Google Analytics landing pages, and add rules for any that carry traffic (e.g. `/coaches/*` Webflow collection paths, if they differed).
  - Do not add a catch-all to the homepage. Keep the real 404.
- Source files: `public/_redirects` (new); optionally the `redirects` block in `astro.config.mjs` (only `/home` there now, and it is also in the file above).
- How we'd know it failed: run `curl -sIL https://harbingermma.com/<old path>` for each old URL after launch and expect a single 301 to a 200. Search Console shows a rise in "Not found (404)".

### 3. [High] Apex vs www canonical mismatch at cutover
- Evidence: the live site redirects `harbingermma.com` to `https://www.harbingermma.com/` (301, Cloudflare), while the new site canonicalizes, publishes sitemaps and builds `site` for the apex (`harbingermma.com`).
- Risk: if DNS cutover keeps apex to www, every canonical points at a URL that redirects, creating a loop-like signal, and the sitemap URLs 301. Search Console properties, GBP and backlinks (mostly on www) are keyed to www.
- Recommendation: pick one host and enforce it in three places. Apex is the cleaner choice and already in code, so on Netlify set apex as the primary domain (www then 301s to apex automatically) and move DNS from Webflow/Cloudflare. Add a `_redirects` safety rule if needed: `https://www.harbingermma.com/* https://harbingermma.com/:splat 301!`. Update GBP, social profiles, Search Console (add a Domain property), and the old Cloudflare redirect rule. If you prefer www, change `site` in `astro.config.mjs` instead.
- Source files: `astro.config.mjs` (`site`), `public/_redirects`, Netlify domain settings.
- How we'd know it failed: `curl -sI https://www.harbingermma.com/ https://harbingermma.com/` shows chains or canonicals on a host that redirects.

### 4. [High] Broken internal link: /classes/mma/ returns 404
- Evidence: the homepage links `/classes/mma/` (404). The sitemap and the class inventory have no MMA page. The old site has /class-types/mma, and the brand is "Harbinger MMA", so the missing page is a content gap too.
- Recommendation: add MMA to the class content collection behind `src/pages/classes/[slug].astro` (preferred), or remove the link. Then change the redirect for `/class-types/mma` to `/classes/mma/`.
- How we'd know it failed: crawl for internal links with 404 status; any non-zero count.

### 5. [Medium] Security headers: only HSTS
- Evidence from `curl -I`: no `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`/frame-ancestors, or `Permissions-Policy`. Also `cache-control: max-age=0, must-revalidate` on HTML (fine) and the same on hashed `/_astro/*` assets was not verified.
- Recommendation: in `public/_headers`:
  ```
  /*
    X-Content-Type-Options: nosniff
    Referrer-Policy: strict-origin-when-cross-origin
    X-Frame-Options: SAMEORIGIN
    Permissions-Policy: camera=(), microphone=(), geolocation=()
  /_astro/*
    Cache-Control: public, max-age=31536000, immutable
  ```
  Add CSP in report-only mode first (inline JSON-LD and module scripts, Google Fonts need allowing). The HSTS `preload` directive is set, so do not submit to the preload list until all subdomains (shop, etc.) are HTTPS.
- Source: new `public/_headers` or `netlify.toml`.
- Failure check: securityheaders.com grade below B.

### 6. [Medium] Netlify injects a script and HTML comment on the public site
- Evidence: `<script async src="/.netlify/scripts/hud?variant=public" ...>` and a Netlify promotional comment are in the head of each page. That is a Netlify deploy-preview/HUD feature and adds a third-party-ish request.
- Recommendation: disable the Netlify HUD/Drawer in site settings or ensure it is not present on production. Not a ranking issue, but it is a small performance and privacy cost.
- Failure check: the script appears in production HTML.

### 7. [Medium] No Open Graph or Twitter tags (cross-ref)
- Known fact. Technical impact is link previews on social and messaging platforms (important for a gym sharing on Instagram, Facebook, texts). Add `og:title`, `og:description`, `og:image` (1200x630), `og:url`, `og:type`, `twitter:card` to the layout head. Source: layout in `src/layouts/` (head component).

### 8. [Low] Astro config inconsistencies
- `astro.config.mjs` `isStaging` uses `NODE_ENV === "staging"` with `base: "/harbinger-2.0/"`. The deployed staging site is served at root with the production `site`, so this branch evidently is not used. It is a trap: if it ever fires, all asset paths and sitemap URLs change. Remove or document it. Generated markup shows Astro v6.4.8 while the context says Astro 5, so confirm the lockfile.
- `image.domains` contains `"://onrender.com"`, which looks malformed. Harmless for static output, but clean it.

### 9. [Low] Hero image has empty alt and a few images lack alt
- Evidence: the hero `<img alt>` is empty (decorative is acceptable if truly decorative); crawl shows 2 images without alt on home, 1 on BJJ. Detail belongs to the content/accessibility reports.

### 10. [Low] Mobile and Core Web Vitals (source inspection only)
- Viewport OK; layout uses Tailwind responsive utilities. No fixed-width problems found. Hero is `loading="eager"` with `fetchpriority="high"` and srcset (good for LCP). Lazy loading is used on only 3 images while the homepage has 14, so check that below-the-fold images have `loading="lazy"` and dimensions. Google Font stylesheet is render-blocking (`display=swap` is set): consider self-hosting Space Grotesk. No lab/field data available (no CrUX for staging). Run PageSpeed Insights on the production domain after cutover.

### 11. [Low] IndexNow not implemented
- Evidence: `/indexnowkey.txt` 404, no key file. Matters mainly for Bing, Yandex and Naver; Google does not support it. For a local gym this is optional. If wanted: generate a key, host `public/<key>.txt`, and ping `https://api.indexnow.org/indexnow` after each production deploy (a Netlify build plugin or deploy-succeeded webhook). Submit only production URLs, never the netlify.app host.

### 12. [Info] Sitemap
- `@astrojs/sitemap` output is valid and includes no lastmod. Consider adding `lastmod` (via `serialize`) and verifying the declared `Sitemap:` URL resolves after launch. Submit in Search Console once on the production host.

## Launch checklist (technical)
1. Staging noindex/Disallow in place now (finding 1).
2. `public/_redirects` deployed and tested with every old URL (finding 2).
3. Decide the host (apex or www), update DNS, `site`, GBP and Search Console (finding 3).
4. Fix /classes/mma/ (finding 4).
5. Add `_headers` (finding 5), OG tags (7).
6. After cutover: confirm production `robots.txt` is `Allow: /`, no noindex headers, sitemap submitted, 301s verified, then remove or keep the staging site noindexed.
